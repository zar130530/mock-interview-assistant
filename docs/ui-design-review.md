# 面试助手智能体 · UI 设计评审与优化方案

> 评审对象：`interview-agent/frontend/index.html`
> 评审日期：2026-08-12
> 评审人：UI Designer
> 目标设备：桌面端（1440px）、平板、移动端（390px）

---

## 1. 设计概览

当前界面已完成一次系统性视觉重构，整体风格**专业、克制、可信赖**，符合“面试教练”产品定位。采用浅灰背景 + 深青色（#0f766e）品牌色 + 卡片化布局，具备完整的设计令牌、响应式断点、骨架屏、Toast 通知、拖拽上传与 API 设置弹窗。

### 1.1 已确认的优点

| 维度 | 优点描述 |
|------|----------|
| 设计系统 | 使用 CSS Variables 统一管理颜色、间距、阴影、圆角、缓动曲线，便于主题扩展。 |
| 品牌表达 | 深青色 + 柔和灰底，避免 AI 产品常见的“紫蓝渐变”，更适合求职工具。 |
| 交互反馈 | 卡片 hover lift、按钮 active scale、Toast 通知替代 alert、骨架屏 loading。 |
| 响应式 | 桌面/平板/移动端三档断点，移动端卡片按钮 2 列换行，触控目标 ≥44px。 |
| 内容组织 | 面板分组清晰（上传简历 / 新建面试 / 列表 / 详情 / 对话修改 / 导出）。 |
| 状态可见 | API 接入横幅、Mock 提示、步骤指示器、题目分类彩色徽章。 |
| 可访问 | 支持 `prefers-reduced-motion`；拖拽区有 `role=button` 和键盘事件。 |

## 2. 逐维度评审

### 2.1 色彩系统

**当前实现**

```css
--bg:#f2f4f8; --surface:#ffffff; --surface-2:#f8fafc;
--ink:#0f172a; --ink-2:#334155; --muted:#64748b; --faint:#94a3b8;
--brand:#0f766e; --brand-2:#115e59; --brand-soft:#ccfbf1;
--ok:#059669; --warn:#d97706; --red:#dc2626; --info:#2563eb;
```

**问题**

- **WCAG AA 对比度风险**：`--faint:#94a3b8` 在白色背景上对比度仅约 **2.4:1**，低于 WCAG AA 对普通文本的 4.5:1 要求。该颜色用于 placeholder、空状态图标、弱化标签。
- `--muted:#64748b` 在 `--bg:#f2f4f8` 上约 **4.5:1**，处于临界值；在 `--surface-2:#f8fafc` 上约 **4.3:1**，略低于 AA。
- 品牌色 `--brand:#0f766e` 与白色文字对比度约 **5.0:1**，刚好及格，但可用性余地不大。

**优化建议**

- 将 `--faint` 提升至 `#64748b` 或 `#718096`，placeholder 颜色使用 `#475569`（对比度约 7.2:1）。
- `--muted` 统一使用 `#475569`，确保在所有浅色背景上 ≥4.5:1。
- 品牌按钮可考虑使用 `#0d9488`（稍亮）或 `#0f766e` + 粗体来补偿对比度。

---

### 2.2 排版系统

**当前实现**

- body `font-size: 14px; line-height: 1.65`
- 标题层级：h1 16px / h2 20px / h3 15.5px
- 正文输入框 14px，题目 `qtext` 14.5px

**问题**

- **中文环境下 14px 偏小**。中文笔画复杂，移动端长时间阅读易产生疲劳。
- 标题与正文差异不够明显（h3 15.5px vs body 14px）。

**优化建议**

- 将正文基准字号从 14px 提升至 **15px**，移动端可保持 15px。
- 标题层级拉开：h1 18px / h2 22px / h3 17px / h4 15px。
- 题目 `qtext` 提升至 16px 并加粗，增强可读性。

---

### 2.3 间距与布局

**当前实现**

- 面板内边距 20px，卡片 15-16px，wrap 最大宽度 1000px。
- 桌面端 wrap `padding: 20px 18px 48px`，移动端 `14px 12px 40px`。

**问题**

- **内容截断缺失导致灾难性视觉膨胀**：详情页 `.kb-note` 直接显示完整 JD，单条记录可把首屏撑到 1000px+ 高度（见 `desktop_detail.png`）。
- `.saved-box .preview` 同样可能展示大量简历文本。
- 列表卡片按钮过多（5 个），即使 2 列换行仍显拥挤。

**优化建议**

- `.kb-note` 增加 `max-height: 4.8em;` + `-webkit-line-clamp: 3;` + “展开/收起”按钮。
- `.saved-box .preview` 限制为 2 行，超出截断。
- 列表卡片按钮精简：主操作“查看”外露；“编辑 / 重新生成 / 删除”收入“更多”下拉；标记状态改用图标切换按钮，减少文案长度。
- 详情页头卡操作按钮在移动端改为图标 + 文字 2 列，或收入底部固定操作栏。

---

### 2.4 响应式设计

**当前实现**

- 断点：`max-width:720px`（移动端）、`max-width:420px`（超小屏）。
- 移动策略：隐藏步骤文字、单列网格、按钮 2 列换行、面板内边距收缩。

**问题**

- 步骤指示器在移动端仅显示数字，**用户无法感知当前所处阶段**。
- 720px 断点对于平板略显不足，可考虑增加 768px 断点。
- 详情页对齐表使用横向滚动，合理，但表头固定可提升体验。

**优化建议**

- 移动端步骤指示器改为底部固定 3 段进度条，或保留“当前步骤名”在数字下方显示（仅当前步骤显示文字）。
- 增加 `@media (max-width:1024px)` 平板断点，优化 2 列布局。
- 技能对齐表增加 `position: sticky` 表头。

---

### 2.5 组件一致性

**当前实现**

- 按钮：primary / ghost / danger / ok / sm / armed
- 徽章：基础圆点徽章 + 状态徽章 + 分类徽章
- 弹窗：API 设置、编辑面试
- 卡片：列表卡片、题目卡片、骨架卡片

**问题**

- **Modal 缺少焦点管理**：打开后焦点未移入输入框，键盘用户按 Tab 会穿透到底层页面。
- **Modal 不支持 Esc 关闭**，关闭按钮使用“×”字符而非语义化 SVG。
- 骨架屏 `.sk` 没有 `aria-hidden="true"` 或 `aria-busy`，屏幕阅读器可能读出无意义内容。
- 题目卡片的 `details` 折叠面板在各题中重复，用户需逐一手动展开。

**优化建议**

- Modal 打开时聚焦首个输入框，并监听 `keydown` 的 Esc 关闭；Tab 循环捕获焦点。
- 关闭按钮改用 SVG + `aria-label="关闭"`。
- 骨架屏容器添加 `aria-busy="true"` 与 `aria-live="polite"`。
- 默认展开第一题的标准回答，引导用户理解“可背诵回答”的使用方式；记住用户展开偏好。

### 2.6 无障碍（WCAG AA 检查）

| 检查项 | 现状 | 评级 |
|--------|------|------|
| 颜色对比度（正文） | faint 文本不达标 | ⚠️ 需改进 |
| 颜色对比度（按钮） | 品牌按钮勉强及格 | ✅ 及格 |
| 键盘导航 | Modal 无焦点陷阱 | ⚠️ 需改进 |
| 屏幕阅读器 | 骨架屏未隐藏，表格无 caption | ⚠️ 需改进 |
| 触控目标 | 按钮高度 ≥44px | ✅ 通过 |
| 动效敏感 | `prefers-reduced-motion` 已支持 | ✅ 通过 |
| 表单标签 | label 与 input 正确关联 | ✅ 通过 |

### 2.7 信息架构与可用性

**当前实现**

- 列表页：上传 → 新建 → 列表三段式
- 详情页：头卡 → 对齐表 → 题目列表 → 对话修改 → 导出

**问题**

- 详情页首屏被超长知识库和 4 个操作按钮严重挤压，**用户需要滚动数屏才能看到第一题**。
- “标记已面试”与“取消已面试”文案过长，在移动端造成按钮换行。
- 对话修改区缺少历史记录，用户无法回顾已发送过的指令。

**优化建议**

- 详情页头卡采用“摘要行 + 展开”模式，默认只显示公司/岗位/状态/生成时间，知识库可展开。
- 头卡操作精简为“返回 / 标记 / 更多（编辑、重新生成、删除）”。
- 对话修改区增加本地历史消息气泡，展示用户指令与 AI 回复摘要。

---

### 2.8 品牌与细节

**问题**

- 缺少 favicon，浏览器标签页显示默认图标。
- 无暗色模式，夜间使用舒适度不足。
- 无 PWA manifest，不能作为独立应用安装。
- 全局滚动条为系统默认，可统一为细滚动条以提升视觉精致度。

**优化建议**

- 制作一个简洁的 favicon（对话气泡 + 对勾或“面”字）。
- 添加 `data-theme="dark"` 的暗色令牌与系统偏好自动切换。
- 生成 `manifest.json` + 512×512 图标，支持安装到桌面/手机主屏。
- 自定义滚动条：`::-webkit-scrollbar` 宽度 8px，滑块品牌色/灰底。

## 3. 优化方案优先级

### P0 — 立即修复（影响可用性或合规）

1. **知识库/简历预览截断**：为 `.kb-note`、`.saved-box .preview` 增加 `line-clamp` 与展开按钮。
2. **提升文字对比度**：`--faint` 至少改为 `#64748b`，placeholder 用 `#475569`。
3. **Modal 焦点与 Esc**：打开时聚焦首个输入框，Esc 关闭，焦点陷阱。
4. **移动端详情页头卡操作精简**：避免首屏被按钮占满。

### P1 — 短期改进（显著提升体验）

5. **列表卡片按钮分组**：主操作外露，次操作收入“更多”菜单。
6. **中文基准字号从 14px 提升到 15px**。
7. **步骤指示器移动端保留语义**：当前步骤显示名称或使用进度条。
8. **骨架屏 ARIA 状态**：添加 `aria-busy` 与 `aria-hidden`。
9. **默认展开第一题标准回答**，引导用户。

### P2 — 中长期增强

10. **暗色模式**：`prefers-color-scheme` + 手动切换。
11. **favicon + PWA manifest**。
12. **对话修改历史记录**。
13. **列表搜索 / 状态筛选 Tab**。
14. **自定义滚动条与更精致的 hover/active 微动效**。

## 5. 总体评价

当前 UI 已达到**可用且美观**的水准，设计方向正确、组件一致性良好、响应式策略基本到位。主要风险集中在**大段文本截断缺失、文字对比度临界、Modal 焦点管理**这三处。按 P0 → P1 → P2 优先级逐步修复后，产品可进入“高完成度”阶段，适合长期作为面试辅助工具使用。
